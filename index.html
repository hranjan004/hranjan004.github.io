Microgrid Manager

Residential energy monitoring · UCSC capstone and continued development

I connected live household energy data, solar telemetry and appliance inference across three electrical panels. Working with Dr. Pat Mantey and AnyLog, I built and debugged the path from meter readings to a usable dashboard, then developed the labeling, training and deployment tools behind the appliance predictions.

I restored live dashboard data by finding a stale table reference: the five-minute reading count went from zero to more than 1,800 in the verification snapshot. I also replaced a hard-coded model exporter with output checks that catch mismatched appliance names before export, preventing an updated model from silently labeling the wrong appliance.

How I used the tools. Kafka carries eGauge readings; AnyLog and PostgreSQL store and query the streams; Solar Assistant supplies measured PV and battery data. I use Python and PyTorch for labeling and training, ONNX for local inference, and Docker for deployment. Node.js, FastAPI and React expose the data and model outputs through dashboards, with Grafana for time-series inspection.

Reliable data and model deployment

The dashboard queried an older ingestion table while new readings were arriving elsewhere. I updated the six query references and checked the snapshot, history and inference endpoints against current data. I also built an archive-gap watchdog that detected a frozen training archive, making the difference between live telemetry and stale training data visible.

When the models gained appliance outputs, the old exporter still assumed a fixed output list. I made export check the configured head names and count, then packaged models, normalization settings, thresholds, appliance mappings and inference code together. The later deployment passed in-container contract checks for all three panels and reloaded the inference loop. Backups preserved a rollback path.

Better labels and chronological evaluation

I retrained across all three panels using a recorded dataset of 705,296 rows, then traced prediction errors back to the source: an incorrect heat-pump power band, a pressure pump assigned to the wrong panel, and appliance heads with no negative labels. Those findings changed the labeling pipeline before further model tuning.

I added physics-based OFF labels, quiet-house negative examples and four-fold walk-forward training, scoring each fold before training on it. Thinly sampled heads report “unmeasured.” These evaluations still rely largely on rule-derived labels, so I treat them as evidence of model behavior rather than independent appliance accuracy. Broader ground-truth validation remains the next step.

Solar integration: tested rules, controlled experiments

I replaced weather-only and fixed-time assumptions in the rules with measured PV and battery snapshots, retaining a fallback for missing telemetry. All 11 solar-path tests passed locally and inside the deployed inference container, including a real-ONNX cycle with a synthetic solar snapshot and no writeback.

I separately compared models with and without four measured solar features on the same 152.6-hour window, using the same split, seed and architecture. Four evaluated heads improved and four regressed; mean F1 changed by only +0.005 against rule-derived labels. I kept that experimental model set out of deployment. Later rolling models added deterministic solar-geometry features across the full archive, avoiding dependence on the short measured-solar history.

Electrical anomaly detection prototype

I built a register inventory and a breaker-margin detector using per-leg current. I checked the panel-to-leg mapping against measured voltage and power, then backtested the detector over 705,177 rows. With hypothetical breaker ratings, it identified one sustained excursion in the historical window. The prototype remains unarmed until actual breaker ratings are supplied; this is a completed backtest, not a deployed safety system.

HTTP / HTTPS forward proxy

Concurrent networking and cache design in C

I built a concurrent C proxy that serves repeat HTTP requests from a shared cache and relays HTTPS traffic through encrypted tunnels. The result combines response reuse with independent client handling and explicit limits on what enters the cache.

I implemented FIFO and LRU eviction on a shared linked-list structure, protected updates with a mutex, and excluded incomplete responses and responses larger than 1 MB. CONNECT tunneling keeps TLS between the client and origin while the proxy relays bytes.

How I used the tools. C and TCP sockets handle request parsing and forwarding. POSIX threads handle concurrent clients; mutexes protect the cache; FIFO and LRU determine eviction. HTTP CONNECT provides HTTPS tunneling.

Engineering details

For HTTPS, I implemented CONNECT tunneling: the proxy opens a TCP connection to the destination and relays encrypted bytes in both directions. TLS stays end to end between client and origin, so the proxy does not terminate TLS or cache the encrypted response as HTTP content. The thread-per-connection design keeps connection handling straightforward; a bounded worker pool is a separate design for controlling concurrency.

Osmosis

FPGA game · CSE 100L, UC Santa Cruz

I built the structural Verilog design for an eight-molecule FPGA game with 640 × 480 VGA output, collisions, randomized movement and timed win/lose states. The provided display testbench completed two frames with zero sync errors and zero RGB-blanking errors.

I fixed a startup bug that placed every molecule at the origin: reset ended before the pixel clock started. Initializing the FPGA flip-flops directly restored the intended positions, which I checked in rendered frames as well as focused timing and game-logic tests.

How I used the tools. Verilog and FDRE primitives implement the game hardware for Basys3 / Artix-7. Icarus Verilog runs timing and state-machine checks; bitmap rendering verifies the actual screen layout; an LFSR varies molecule positions, speeds and directions.

Engineering details

Full-game simulation was expensive with the clock primitives and continuously toggling LFSR. I used Icarus Verilog with behavioral primitive stubs, a directly driven pixel clock for VGA checks, and accelerated frame pulses for game-logic tests. Rendering an idle frame to a bitmap exposed placement errors that passing sync and FSM tests had missed.

GPT-2 CPU performance analysis

Computer architecture · UC San Diego summer session

I reduced the observed L1 data-cache miss rate in GPT-2 CPU kernels from roughly 9% to 2–3% using cache tiling and AVX2 vectorization. I kept the existing test drivers and avoided adding libraries, making the optimization a focused change to the computation.

I used Linux perf to find the bottleneck first: backward matrix multiplication accounted for about a third of sampled cycles. Hardware counters then showed how the changes improved data reuse. The measured result is kernel memory behavior; a whole-program speedup was not established.

How I used the tools. Linux perf identifies hot functions and cache misses. C loop tiling keeps reused data close to the processor; AVX2 processes multiple values per instruction. OpenMP, TLB and NUMA experiments explore scaling and memory locality.

Engineering details

I also studied OpenMP thread scaling against Amdahl’s law, TLB behavior across page sizes and NUMA locality. The work taught me to separate kernel-level improvements from whole-program speedup and to use hardware counters to explain where an optimization helped.

Two-player Quick Add

Structural RTL game controller · Basys3 FPGA

I expanded a single-player arithmetic game into a two-player FPGA design with shared response windows, independent scores and win/loss/tie handling. A nine-state controller synchronizes each round and remembers both players’ answers.

I fixed a one-cycle mismatch between score updates and game-over detection that allowed an extra round after a player reached zero. Both Icarus Verilog testbenches passed after the fix, covering simultaneous answers, ties, no-response rounds and game-over lockout.

How I used the tools. Structural Verilog and FDRE flip-flops implement the Basys3 controller. Two-flop synchronizers capture button inputs; a one-hot FSM resolves rounds; Icarus Verilog state traces expose timing errors and verify the fix.

Engineering details

I checked the fix with a focused state trace, then ran both verification testbenches in Icarus Verilog. The recorded scenarios passed for solo wins and losses, ties, both players losing, neither player pressing, game-over lockout and the debug switch modes.

Spiking neural networks

Brain-inspired machine-learning experiments

I built a convolutional spiking-neural-network training pipeline for CIFAR-10 to study learning over time. It combines Poisson input encoding, threshold-dependent batch normalization and learnable membrane decay.

I investigated layers that stopped spiking and adjusted the encoding and neuron dynamics to understand training instability. The next deliverable is a reproducible accuracy and latency comparison against a conventional convolutional network; efficiency gains are not yet measured.

How I used the tools. PyTorch and snnTorch implement training and neuron dynamics. Poisson encoding converts images into spike sequences; surrogate gradients enable training; threshold-dependent batch normalization helps control activation behavior.
