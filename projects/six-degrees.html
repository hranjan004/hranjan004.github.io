The problem

A connection finder needs to return more than a distance: the user should see which shared films connect the actors.

How I approached it

I parsed cast lists, mapped actor and movie names to integer IDs and stored movie IDs with actor-to-actor edges.

Breadth-first search tracks visited actors and records both the previous actor and the film used to reach each node. I reconstruct the path from that parent map.

What changed

Built a file-driven graph query program that expresses the connection as an actor-and-film chain.

Worked through parsing, disconnected inputs and path reconstruction rather than treating traversal alone as the finished feature.

The archived implementation uses pairwise cast connections; a movie with a large cast can create many edges. No large-dataset performance claim is made.

Engineering decisions

BFS finds a shortest path by edge count in an unweighted graph. Keeping movie identity on the predecessor edge preserves an explanation of why each connection exists.
