The opportunity

The hack.dev UCSC AI hackathon was an opportunity to extend Microgrid Manager from monitoring into local reasoning and forecasting. I brought training, inference and data services together on the GX10 while keeping each prediction tied to an explicit data and model contract.

What I engineered

I deployed the stack on the GX10’s Grace Blackwell platform: GB10 GPU training, ARM-compatible data services and local serving. Recorded meter data enabled a self-contained event demo; read-only meter and solar collection later added direct-source inputs.

I built the physics-labeling and rolling walk-forward training path for panel-specific BiLSTMs, preserving an 18-feature normalization contract and calibrated ONNX exports.

I distilled the gated BiLSTM into Nemotron 3.5 Lightning with rank-16 LoRA. Each round merges the adapter, scores held-out windows and refreshes a fixed-size training replay buffer. The live Q8_0 model serves through llama.cpp with per-head BiLSTM fallback.

I separated question answering from appliance inference: Ollama serves the reasoning interface, while the fine-tuned model produces structured appliance states. The system map combines verified deployment topology with separately labeled extracted relationships.

For power forecasts, I compared TiDE-inspired PyTorch, CUDA XGBoost, seasonal baselines and blends using meter history, weather and missingness flags. Versioned models and an atomic champion pointer let retraining proceed while serving continues.

The results

Reached 91.91% held-out agreement with the gated BiLSTM teacher on 300 validation windows, up from 82.14% in the first round.

Deployed the quantized local NILM engine with per-head fallback. Q8_0 matched the merged BF16 model on 166 of 176 head decisions in the recorded comparison.

Built a forecasting dataset from more than 30.7 million deduplicated meter records across 16 channels and roughly 977,000 solar records, with coverage filters that preserve missing intervals.

Added prediction and system-map views with minute-level forecast refresh and 15-minute forecast origins. Model promotion requires at least 1% improvement in normalized MAE on shared validation origins.

Why it matters

Model training and live serving share one machine, so versioning and promotion rules are part of the model design. Separating appliance states, forecasts and conversational answers gives each output a clear job and evaluation.

Engineering decisions & measurement context

The NILM input contract uses 100 × 18 windows. The teacher target includes the same mutual-exclusion and power gates used in serving, rather than copying raw recall-biased network outputs. Hard-example mining draws from training data, never the held-out validation split.

Forecast selection, empirical interval calibration and final testing use three disjoint 14-day blocks. Training windows cannot cross split boundaries, and normalization is fitted only on training data. Historical weather inputs use previously issued forecasts rather than realized future observations.

Prediction intervals come from calibration residuals per channel and horizon. Reported test coverage can fall below the nominal 80%, so the dashboard exposes observed coverage rather than promising certainty.

Forecasts require sufficient recent source coverage. Replay timestamps do not count as new live data for retraining, missing measured PV can withhold the solar baseline, and later direct-source collection provides provenance without Docker-control permissions.

Local training, model serving and data services share the GX10 memory pool. I separated model evaluation, merge, quantization and serving stages, retained model backups and fixed export handling so external ONNX weight files were not silently omitted from deployment.

The 91.91% result measures distillation agreement with the gated BiLSTM teacher on 300 held-out windows. It is not independent, submetered appliance accuracy. The recorded deployment used six-hour retraining checks; candidate promotion preserves the current serving model when the required improvement is not met.
