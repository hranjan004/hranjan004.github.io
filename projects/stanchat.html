The problem

A short MVP timeline calls for one useful vertical slice: write a message, see it appear and keep conversation history available.

How I approached it

I moved toward Flutter for a shared cross-platform interface and Firebase for managed storage. The chat screen listens to Firestore message updates and writes text with timestamps.

I worked through FlutterFire setup, dependency conflicts and Android emulator configuration, prioritizing the message path before additional account features.

What changed

Built a local message flow: send a message, see it in the conversation, and scroll back through earlier messages.

Reached a working local chat prototype; broader release and account workflows were later milestones.

What I took from it

Getting a message from the composer into the conversation view made the data flow concrete. The local prototype supports sending, displaying and scrolling through messages; account workflows and broader device testing are the next steps.

Engineering decisions

A stream-driven interface updates the conversation when stored messages change. Database permissions and identity become essential before expanding a local demonstration into a shared public service.
