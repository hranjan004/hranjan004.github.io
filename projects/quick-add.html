The problem

Expanding a single-player game requires a shared response window, independent player state and correct handling of simultaneous inputs.

How I approached it

I used synchronized and latched button inputs so both players could answer in the same round.

I traced a one-cycle mismatch between score updates and game-over detection, then added the missing transitions that prevented an extra round at zero points.

What changed

Both recorded testbenches passed after the fix, including ties, simultaneous wrong answers, no-response rounds and game-over lockout.

The project demonstrates structural control logic and focused verification.

Engineering decisions

Two-flop synchronizers bring button signals into the clock domain; round latches retain each player’s response. The one-hot FSM resolves the shared window into scoring and the next round.

The score register and game controller observe values on clock boundaries. Explicit game-over transitions handle the updated score on the following cycle rather than assuming it is immediately visible.
