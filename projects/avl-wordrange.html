The problem

A word index needs to accept insertions while answering how many entries lie between two keys. An unbalanced tree or a full traversal makes those queries unnecessarily expensive.

How I approached it

I worked on an AVL tree that stores both height and subtree size, with rotations maintaining balance and the metadata needed for rank queries.

I traced zero and negative range counts through size updates, rotation order and comparisons, distinguishing numeric-looking strings from the assignment’s lexicographic keys.

What changed

Implemented the indexed-query coursework and investigated failures with explicit insertion sequences and expected range counts.

The intended design answers a range count using two rank traversals rather than enumerating every matching node.

Logarithmic query complexity is a property of the correctly maintained AVL design, not a measured speedup. The archive includes debugging cases without a final comprehensive pass report.

Engineering decisions

For inclusive bounds, count(keys ≤ upper) − count(keys < lower) handles the boundary correctly. Heights and sizes must be recomputed after rotations in child-before-parent order.
