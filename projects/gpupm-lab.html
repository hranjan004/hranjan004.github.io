The problem

A power-state request is not just a new frequency value. Voltage and clock changes must happen in a safe order, concurrent callers must agree on ownership, and a lost completion or stalled controller must not leave the next request in an unsafe state. I built an emulated controller and a real Linux platform driver to exercise that entire contract.

How I approached it

I defined a shared C register-level model with four synthetic P-states, power-budget admission, thermal constraints, write-one-to-clear interrupt status and injectable faults. On a boost, voltage rises before frequency; on a downshift, frequency falls before voltage.

I implemented a Linux platform driver with a transaction mutex for request ownership and an IRQ-safe spinlock for register access. Delayed work advances the controller, a software IRQ handler acknowledges completion, and sysfs exposes controls and status to a C CLI.

I designed timeout recovery to drain outstanding work before reusing a completion. Terminal status can recover a lost notification; a still-busy controller aborts to safe P3. This prevents a stale callback from satisfying a later request.

I packaged a matching ARM64 kernel, module, CLI and initramfs through Docker, then booted the integration suite in disposable QEMU. The same controller also runs in a native pthread harness for fast model tests and sanitizer checks.

What changed

Validated all 16 state pairs, 10,000 randomized transitions and 50,000 adversarial register writes/ticks, alongside native address and undefined-behavior sanitizer checks.

The Linux guest completed 400 concurrent sysfs requests, fault-recovery checks, active-client removal and 10 module reload cycles. The tested kernel was Linux 6.1.190 ARM64.

Measured 200 alternating P0/P3 requests per backend: native-emulator p95 was 3.898 ms and QEMU sysfs p95 was 25.218 ms. These characterize the software request paths and scheduling, not physical GPU transitions.

What I took from it

The most important design decision was who owns an in-flight transition. Holding the transaction lock through completion and draining old work before the next request made concurrency and recovery easier to reason about. This completed emulation lab provides a testable foundation for a future real-bus backend.

Engineering decisions

The shared model makes each voltage/frequency step inspectable. CURRENT stays at the last committed P-state until completion, while instantaneous voltage and frequency expose the intermediate transition.

The worker invokes the common interrupt handler in software. The QEMU guest validates Linux synchronization and lifecycle behavior; physical interrupt delivery and MMIO bus ordering require a separate hardware or virtual-device backend.

The controller uses invented electrical values and explicit thermal injection. It demonstrates power-management mechanisms without claiming to control an NVIDIA GPU or measure real GPU power.

CI runs native tests, sanitizers and Linux module compilation. The QEMU end-to-end suite is separately reproducible, with saved console evidence and a required pass marker.
