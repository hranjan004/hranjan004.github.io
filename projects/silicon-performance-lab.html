The opportunity

Performance work needs a repeatable workload, a verified answer and a clean measurement interval. I built a lab that connects those three across Apple Core ML, FPGA graphics and a custom host/device runtime.

What I engineered

I built SPL2, a C++17 asynchronous runtime with futures and up to 16 outstanding jobs. CRC-protected UART frames, request epochs, credit-based flow control and watchdog recovery coordinate the host and FPGA.

I implemented banked vectors and 1/2/4/8-lane dot-product and XOR-reduction kernels. Timing sweeps selected eight lanes at 30 MHz.

In a separate graphics image, I built integer compute lanes, BRAM transfers and a Verilog triangle rasterizer. A 64×64 framebuffer feeds independent 640×480 RGB444 DVI scanout; UART supports commands and framebuffer readback.

I validated raster pixels against a software reference, simulated a complete frame, then synthesized, routed and exercised the physical iCEBreaker. The UART runner records cycle counts and host latency for every checked transaction.

I wrote a Swift Core ML runner for a deterministic four-layer convolution workload and a JavaScript / Node.js dashboard for controls, latency charts and exports. Five warmups and three 50-prediction trials separate execution timing from compilation, loading and output checks.

The results

Validated 12,000 SPL2 jobs on the physical iCEBreaker. A 10,000-job run at queue depth 16 sustained 702.266 jobs/s versus 62.5021 at depth 1—an 11.2× throughput improvement.

Eight lanes complete a 256-pair dot product or XOR reduction in 35 device cycles versus 259 with one lane: 7.4× fewer cycles. At 30 MHz, the device calculation takes 1.167 microseconds.

The selected image uses 3,835 of 5,280 logic cells, all 30 RAM blocks and all eight DSP blocks; routed timing reached 31.219 MHz. Three invalid-vector requests were rejected and followed by successful epoch recoveries.

The separate graphics image passed 2,113 physical transactions: 938 compute, 938 memory and 237 raster runs. The external monitor displayed the rendered triangle; simulation checked 420,000 pixel periods.

The saved M4 experiment measured 0.154 ms median CPU-only prediction latency and 0.139 ms for CPU + Neural Engine, with all 131,072 output elements checked against the CPU reference.

Passed 13 dashboard/server and data-contract tests plus eight host-protocol and power-integration tests.

Why it matters

Keeping work in flight raised throughput 11.2×; adding lanes cut device cycles 7.4×. Measuring both identifies the next optimization target: transport and host overhead.

Engineering decisions & measurement context

SPL2 is a separate compute-only image; it does not include the earlier DVI rasterizer. The October 25 graphics results and October 29 SPL2 results describe different bitstreams. UART simulation reached about 2,965 jobs/s; physical hardware measured 702 jobs/s. The physical 80%-of-link-ceiling target remains unmet.

Core ML compute policies allow CPU fallback. Preferred-device information is scheduling evidence, so I do not treat it as a trace proving which accelerator executed every operation. The saved run was taken on battery power; repeated independent runs on AC power would support stronger comparisons.

Video scanout runs independently of the UART request path. Hardware returned the expected 4,096 raster cycles and framebuffer pixels; configured-clock throughput is distinct from host round-trip timing. The repeated serial test does not saturate the compute engine or measure maximum board power.

The FPGA is fixed-function graphics hardware. It renders a fixed triangle and supports defined compute and memory exercises; it is not a general shader processor.

Energy analysis requires measured power covering the same interval as completed work. The integration code is tested, while physical watts, joules and work-per-joule measurements remain future experiments.

The 702 jobs/s result comes from a roughly 15-second sustained run, not long-duration qualification. The physical link reached 22.5% of its ideal response ceiling. Timing sweeps excluded a 36 MHz candidate that did not meet timing.
