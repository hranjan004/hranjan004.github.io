Project

Completed

Tools used

The problem

A C GPT-2 training loop spent much of its CPU time in matrix multiplication. Parallelism was constrained by the course build environment, so I started by improving the serial kernels.

How I approached it

Linux perf identified backward matrix multiplication at 33.09% of sampled cycles and forward multiplication at 23.88%. That evidence set the optimization order.

I tiled the computation to improve data reuse and used AVX2 fused multiply-add instructions to process eight floats at a time. I worked within the existing test-driver and library constraints.

Related experiments examined thread scaling, page-size effects and NUMA locality to connect software changes with processor behavior.

What changed

Follow-up profiling reported a reduction in the hot kernel’s L1 data-cache miss rate from 9.17% to approximately 2–3%.

The project produced a concrete link between memory access patterns, vectorized computation and hardware-counter measurements.

This is a kernel cache-behavior result. The archived material does not establish a reproducible end-to-end training speedup.

Engineering decisions

The optimization targets memory reuse inside matrix multiplication. Tiling changes the working set; AVX2 changes the arithmetic issued per instruction. These mechanisms need separate measurements because lower cache-miss rates alone do not establish total speedup.

The benchmark account should retain compiler flags, matrix dimensions and thread settings. The published portfolio metric remains the measured cache-miss change rather than an inferred training-throughput figure.
