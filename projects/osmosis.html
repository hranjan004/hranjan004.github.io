The problem

The challenge was to build a playable VGA game under strict structural-RTL constraints: continuous assignments and flip-flop primitives, with no procedural blocks in the hardware design.

How I approached it

I separated pixel timing from frame-based movement and composed collision handling, membrane controls, randomized motion, a timer and win/lose state logic.

When every molecule appeared at the origin, I traced the failure to reset ending before the derived clock began. FDRE initialization parameters established the intended positions at configuration time.

I used behavioral simulation stubs, focused timing and game-logic tests, and bitmap rendering to check both the logic and the actual visible output.

What changed

The provided display testbench completed two frames with zero sync errors and zero RGB-blanking errors.

Implemented eight moving molecules, color-selective membrane control and randomized positions, speeds and directions.

What I took from it

The satisfying part was connecting small synchronous components into a visible, interactive system. Frame timing, membrane rules and molecule state all had to agree before the display behaved like a game.

Engineering decisions

Pixel counters produce display coordinates and blanking signals; frame pulses advance object motion. Separating these time scales keeps collision and game-state updates independent of pixel traversal.

Configuration-time FDRE INIT values solve a different problem from synchronous runtime reset. The start-position failure required checking the clock-start sequence and rendered pixels, not just the state-machine transitions.
