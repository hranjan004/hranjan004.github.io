The problem

Computer architecture can remain abstract when the datapath and control signals are hidden inside a processor. A discrete build makes those boundaries visible.

How I approached it

I developed a proposal covering the ALU, register bank, program counter, instruction storage, shared bus and control sequence.

I organized the work into module-level checks, integration, simple instruction programs and documentation, with a component budget and a staged build schedule.

What changed

Produced the architecture, build sequence and funding proposal.

A functioning assembled computer remains a future hardware milestone.

The archive documents a proposal and research, not completed hardware, awarded funding or measured processor performance.

Engineering decisions

The proposed integration checks include bus contention, clock distribution and control timing. Each datapath module needs independent verification before the fetch–decode–execute sequence can be validated.
